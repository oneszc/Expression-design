# 制作模式、风格与主题选择

在制作任何方案前确定模式，规划样张前补齐创作偏好。入口统一收集模式、风格、主题三组选择，已知项跳过。风格与主题选项参考用户提供的选择界面，是创作辅助分类，不代表微信平台审核分类或比例要求。

## 三组选择

**制作模式：静态／动态，单选。**

- 静态：每张是一幅独立表情图。
- 动态：每张是一段实际循环动画；方向样张也需展示动态效果。

不预选为已确认答案，不把静态样张冒充动态。用户明确要求混合模式时先澄清交付范围，再按实际模式分别规划与校验，不悄悄丢弃其中一种。

**表情风格：建议选择 1～2 项，也可以自行描述。**

日常、软萌可爱、二次元、长辈风、搞笑、丧/佛系、魔性鬼畜、恶搞、简笔画、赛博朋克、蒸汽波、像素、暗黑、复古、**其它，自行输入**。

这些选项混合了视觉画风和表达气质，可以组合使用，如“简笔画＋丧/佛系”。不将每个标签都强行变成一种绘画技法；“日常”也不代表主题只能选万能通用。用户需要更多风格时按其明确要求处理；风格确实冲突时只澄清影响结果的冲突。

**表情主题：选择一个主主题，也可以自行描述。**

万能通用、网络热点、节日、考试/学习、工作/职场、情侣、毕业、刷屏、红包相关、游戏、运动/健身、怼人/斗图、群聊必备、节气、邀约/约起来、励志鼓舞、**其它，自行输入**。

主题决定聊天场景与表达规划，不只改变标题。用户自定义具体主题或指定表情清单时优先沿用，例如“周一不想上班”保留为具体主题，可辅助归类工作/职场；不能用大类覆盖原意。用户明确需要混合主题时保留各主题，不强迫改成单一主题。涉及“网络热点”等时效内容时，再核实具体事件，不凭标签编造当前热点；要求搜热门表情作为参考时读 [联网参考与特征提炼](research.md)，不自动把所有网络梗创作变成热门调研。

## 什么时候询问

- 先读用户文字、参考图及已有项目。明确的风格与主题直接记录，不再弹窗；对普通推断标明依据，不冒称用户选择。
- 已有角色要求延续时，画风记为“沿用参考图”，只在表达气质仍影响结果时补问；选择“搞笑”等气质不授权改变角色画风。主题仍可独立选择。
- 只缺一组就问一组；多组都缺时尽量在同一轮按“制作模式 → 表情风格 → 表情主题”询问，最多三个核心问题。不先弹一个模式问题、回答后再重复弹完整三组，也不再同时堆数量、配字、名称等问题。
- 风格与主题选定不代表已经选定角色。只有主题的路径仍按 SKILL.md 展示实际方向样张；已有形象路径仍跳过角色方向对比。
- 等待回答时可以检查工具与依赖，不能先按未经选择的风格生成素材。用户明确让 Agent 自行决定或跳过选择时，可说明采用的偏好后继续，不强迫走表单。

## 弹窗与文字回退

1. 检查本轮实际可用的提问工具和参数能力。优先使用支持选项与自定义文本的原生问答卡片/弹窗；Skill 只定义问题和选项，不直接创建或控制客户端模态窗口。不能为了弹窗擅自切换运行模式、安装插件或新建网页应用。
2. 风格控件支持多选时允许选 1～2 项；仅支持单选时如实说明，允许用户在自由输入中写“简笔画＋丧/佛系”，不把单选伪装成多选，也不把第一个预选项当作已提交答案。
3. 风格、主题两组都需要自由输入。工具自动提供“其它”或自由输入入口时，复用该入口，不再添加同义选项；工具需要显式选项时，加入“其它，自行输入”。用户选了其它却未填内容时，只追问该组的具体描述，不替用户猜。模式默认提供静态、动态两个选项，平台自带的自由输入仍按用户实际意图处理。
4. 工具无法容纳完整选项时，先用文字展示完整列表，再用自由输入卡片接收名称/组合；没有可用提问工具时，直接让用户用文字回复。不能静默只留下几个类别，让用户以为没有其他选项。
5. 记录并沿用用户提交的实际值。自由输入即使不在列表中也有效；分类只是索引，不能丢弃具体描述。不要求用户再次确认普通选择。

文字回退示例：

> 制作模式选静态或动态；表情风格建议选 1～2 项，表情主题选一个主主题，风格和主题都支持其它内容。可以回复“模式：动态；风格：简笔画＋丧/佛系；主题：工作/职场”，或者直接写“模式：静态；风格：其它，铅笔涂鸦；主题：其它，养猫人的日常”。

使用此示例前展示上面的完整选项；已知的组省略，不重复问。

## 选择如何影响制作

在 `project.md` 记录实际值与来源，如“风格：简笔画＋丧/佛系（用户选择）；主题：周一不想上班（用户原文，辅助分类工作/职场）”。无需为了分类改动交付 manifest 的字段。

方向探索在所选风格范围内比较轮廓、比例、表情语言和线条；`expressions.md` 围绕所选主题设计语义、动作与配字。主题是工作/职场时，要有具体聊天处境与语气；不能仅把一套通用喜怒哀乐换成职场标题。配套素材继续沿用选定风格与角色。
