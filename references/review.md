# 独立评审与返修

生成结果先交独立子 Agent 评审，通过后主 Agent 才主动展示、复制到交付目录或加入 ZIP。这是制作流程中的实际调用，不是让主 Agent 换个口吻给自己的作品打分。

## 能力与边界

在出图前检查本轮是否支持子 Agent，以及评审 Agent 能否访问实际参考图、候选文件和必要的图像/播放工具。可用时调用宿主提供的子 Agent 工具，不绑定某个厂商、模型或不存在的角色名。不支持独立子 Agent 时说明缺失，可继续准备表达规划，但不把主 Agent 自评记为独立评审，也不开始无评审保障的批量出图；用户明确接受人工验收/自评替代时，记录该例外。

候选放在项目 `previews/candidates/` 等本地过程目录，不作为已验收素材暴露。优先采用不自动向用户展示过程图的生成方式；若当前工具会自动展示生成预览且无法关闭，出图前说明无法保证“评审前完全不可见”，不假装工具返回的预览已经通过。主 Agent 仍只主动展示评审合格版本；不为绕过这一限制擅自更换付费服务、接口或安装工具。

分数是基于给定标准的设计判断，不是客观质量保证，也不替代用户选择或微信审核。不能为了达到门槛改低评分标准。

## 实际评审调用

主 Agent 提供给子 Agent：

- 用户原始需求、已确定的模式/风格/主题、适用阶段（方向草样或最终交付）与本次范围。
- `project.md`、`expressions.md`、实际角色参考图；方向探索尚未选定角色时，提供方向约束，不把尚未选角色当成缺陷。
- 本轮候选的精确路径、SHA-256、素材用途、对应含义与配字、背景要求，以及真实尺寸/体积/编码检查结果。动态另提供最终 GIF、浅/深底解码帧对照、源帧时长和动作计划；关键姿态要能对应准备、主动作、恢复等阶段，不强制每一帧另写描述，不能仅给九宫格或成功日志。
- 本文件的评分标准。返修轮另给上一轮实际缺陷和本轮修改范围，不给预设分数或“应该通过”的暗示。

在宿主支持时使用不继承整段制作对话的独立上下文，把上述输入明确传入。评审 Agent 自行打开实际图片；动态需查看最终文件全部帧、浅/深底，并观察原速至少两轮。不能用生成提示词、主 Agent 的描述、文件可解码或一张截图代替观看。静态也要在实际交付尺寸和浅/深底看边缘；图标查看50px效果。

当前用户明确要求优先于旧项目记录；任务清单与源清单的阶段/背景不一致时记录差异，不能把文件标为draft就免除当前最终交付检查。无法确定会影响验收的实际要求时列为证据不足，不擅自改要求。原速观察须来自评审 Agent 能实际感知连续时序的动图/视频工具，记录文件、速度、循环次数、所用观察方式及具体转场所见；播放器打开成功、等待两轮的时长或截图轮询均不能单独证明已观察连续播放。

子 Agent 只读评审与返回意见，不重画、不修改素材，不提交或发布。它不决定用户必须喜欢哪个角色，方向草样通过只说明可供选择，不代表用户已经选中。

## 评分与通过条件

每个候选表情及配套素材分别按以下四维给整数分，满分100；每维说明具体画面证据与扣分原因：

| 维度 | 满分 | 判断要点 |
|---|---:|---|
| 角色与风格一致性 | 25 | 辨识特征、比例、线条/材质与参考/已选方向相符；不擅自改角色 |
| 表达与需求匹配 | 25 | 说明具体聊天场景、主题如何体现在画面/配字里，以及笑点、反差或语气；动作可读，配套素材体现同一套设计 |
| 制作质量 | 35 | 动态：表演自然15、位置/形体稳定10、恢复/循环10；静态：线条与细节15、形体与剪影10、边缘/透明10 |
| 聊天尺寸可用性 | 15 | 文字正确清楚、主体留白合理、浅深底可辨；配套素材按其真实尺寸和用途判断 |

总分 **>80**（整数即81～100）才满足分数条件；80分不通过。每项均需通过，不能取整套平均分代替单项门槛。缺少必要观察时，相关维度和总分记为未完成（结构化记录用null），可以保留其他已完成维度的分数与证据；结论为 `blocked`（证据不足），列明未检查项，不用0分或满分替代未知。

表达维度还需至少18/25，避免精致但不切题的结果靠其他项补分：22～25为具体场景和表达鲜明；18～21为主题清楚、表达成立；13～17为通用姿态换字、具体主题或语气不足；0～12为误解含义或主题。文字本身可构成梗，不强制无字也能识别所有主题；用于普通确认的表情也不强求每张都搞笑。评分看用户要求，不把评审 Agent 的个人审美当成用户口味。

以下任一项为关键缺陷，即使高分也必须返修：错角色/违背明确要求、明显多余或缺失肢体/接触穿插、错误配字、主体被裁掉、假透明或身体填充丢失、非设计的明显位置跳变/循环瞬移、动态实际为静态，或实际文件不满足当前阶段必需规格。静态PNG不因没有动态扣分；草样可用少量姿态，但仍不能有关键缺陷，且不能把草样通过写成最终质量通过。

最终配套图另按 [微信规范](wechat-delivery.md) 检查背景、文字、构图、白描边、锯齿与用途，不能把“参考图是白色角色”当成白底封面合理的依据。最终报告须声明对应的banner_design/cover_design/icon_design并提供platform_evidence；名称/介绍长度由程序检查，文案准确、名称查重与已知专辑封面/图标重复需写实际核对范围。当前规范更新优先于旧案例的白底/配字做法，不追认旧评分。
最终交付须通过随附文件规格校验；方向草样也须检查真实编码、边缘与目标尺寸下的可读性，不要求草样已经拥有整套配套素材。脚本检查通过不等于视觉通过。

整套单项通过后，再由独立子 Agent 横向检查角色、画风、基准比例、配字位置、语义和动作区别，以及横幅/封面/图标的关联。给整套0～100整数分和具体证据，同样要求>80、无关键缺陷且无必要检查缺项；发现重复动作或风格失配时指出具体文件，不能只给一个笼统总分。

## 返修闭环与记录

1. 首次生成记为第0轮。评审记录保存至项目 `reviews/轮次/`，逐项包含阶段、文件路径与SHA-256、实际评审 Agent 标识、已观察/未观察项、四维分数与依据、总分或证据不足、关键缺陷、结论（`pass` / `revise` / `blocked`）和具体修复建议；整套结果另列。只有实际完成评审的 Agent 才能署名。
2. `revise`：只重做/局部修复对应问题，尺寸或排版错误优先精确修正；角色或关键姿态错误再生成，不盲目整套重抽。最多自动返修2轮（即每项最多3个候选版本），所有版本使用新路径，保留旧报告。
3. 修改后重新计算SHA-256，必须由独立子 Agent 查看新文件并重新评分。不能沿用旧分数；分数相同也要有本轮观察依据。只改了一张时复评该张及受影响的整套关系，其他未变项可复用与文件哈希对应的评审。
4. `blocked`：先处理缺失证据/工具能力；没有原速观察能力时停止该评审路线，不靠反复生图解决缺少播放检查。达到返修上限仍失败时停止自动生成，只向用户报告未过项、原因及可选下一步，不偷偷降门槛、突破预算或把失败样张塞进交付包。用户明确要求继续时再开启额外轮次。
5. 主 Agent 核对逐项分数相加、>80门槛、表达至少18/25、关键缺陷为空、必要检查完整、当前路径与哈希匹配、整套结果通过，再主动展示。方向样张也要过门槛；只准备出部分合格方向时如实说明缺项，不混入未过项凑数。最终评审采用 [固定报告格式与受检打包](review-report.md)，使用随附脚本核对后生成正式ZIP，不以口头“已通过”代替检查。

样张通过后仍按 SKILL.md 让用户选择方向，不新增一次“是否允许评审”的确认。用户明确要求查看失败过程图时可以展示并说明分数、缺陷与状态；这个请求不等于把它改判合格。所有报告和失败候选沿用本地产物忽略规则，不随 Skill 提交GitHub。

## 评审任务示例

> 你是独立表情评审 Agent，只读检查。依据提供的用户需求、角色参考、阶段和本文件，打开清单内实际候选文件。逐项检查并给四维分数、扣分证据、关键缺陷和pass/revise/blocked结论；总分须>80且检查完整才可pass。任何看不到的画面/播放如实标为未检查，不推测通过。只返回评审，不生成、不改文件。最后对本轮整套/方向批次横向检查并评分，指出对应文件。不要为了满足目标分数而调整标准。
