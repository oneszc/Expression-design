# 动态表情制作

动态在入口确定，方向对比也应展示真实短循环。可用帧绘制、图像模型逐帧编辑、动画工具或代码动画；选择能保持目标角色和画风的可用方案。只有静态生图工具时，不宣称已具备动态制作能力。

## 动作设计

把每张表情写成“初始姿态 → 准备 → 主动作 → 停顿/回弹 → 回到起点”。动作服务聊天含义，例如“收到”可以是一次点头加抬手，“无语”可以是缓慢侧目加停顿，避免整套只用抖动、缩放。

时长和帧率按动作决定，可从 1～3 秒、每秒 8～15 帧开始试，这是制作起点，不是微信平台硬规则。夸张动作仍需维持头身比例、标志配饰和角色辨识度。

保持统一画布、相机、锚点和基准比例。生成帧时逐帧引用角色参考和关键姿态，避免每帧独立随机重画造成身份、线条和材质闪烁。

## 渲染与导出

1. 先看关键帧，再渲染短循环。已有形象直接沿用，不为做动画重设角色。
2. 保留动画源文件或帧序列，以及对应帧时长。
3. 导出真实 240×240 动画 GIF，设置循环。不能把单帧 PNG 改扩展名，不能把静态 GIF 当成动态交付。
4. 全部帧使用一致的调色板/透明索引策略；按内容选择 disposal，检查透明背景上前帧残留与闪边。GIF 透明度有限，柔边需在浅/深背景实看。
5. 超过体积时依次考虑优化调色板、删掉冗余帧、调整帧率与时长。不能为了压缩把动作做成无法辨认的两帧跳变。

## 检查

- 用实际播放看节拍与首尾衔接，并逐帧看角色变形、闪烁、拖影、缺帧。
- 字幕不要随帧跳位，除非动作设计有意如此。
- 在聊天大小、浅色和深色背景检查透明边缘与动作可读性。
- 重新播放最终压缩的 GIF；源动画流畅不等于导出文件流畅。
- 帧数和循环字段只是技术检查，不能替代观看动画。
