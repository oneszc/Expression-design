# 动态表情制作

动态在入口确定，方向对比也应展示真实短循环。可用帧绘制、图像模型逐帧编辑、动画工具或代码动画；选择能保持目标角色和画风的可用方案。只有静态生图工具时，不宣称已具备动态制作能力。

## 制作路线与小样验证

先按 [环境与工具选择](environment.md) 确认可用能力，再按角色和画风选路线：

- 简单轮廓、固定配饰、重复使用的肢体：优先复用角色母版和分层素材，以图层/矢量/时间线控制眼睛、嘴、肢体和道具；保留原画风，不为了方便动画擅自重设计。
- 手绘、材质复杂或需要大幅形变：使用可保持角色的逐帧绘制、关键姿态局部编辑或可用动画工具。先验证连续姿态，检查身份与材质稳定性，再决定是否批量制作。
- 生图网格适合探索关键姿态，不默认作为最终动画源。进入整套制作前，验证独立帧提取、帧边界、固定特征、原速节拍和循环均可接受；反复出现身份漂移或肢体错误时，改用素材复用、局部绘制或其他可用路线，而非持续整张重抽。更换工具仍需先通过环境检查。

使用同一选定角色的少量样张覆盖小动作、表情变化、大幅运动，验证这条路线后再扩展；这是制作验证，不重新触发角色方向选择。只有用户明确要求直接批量时可直接执行，但仍逐张检查。

## 动作设计

把每张表情写成“初始姿态 → 准备 → 主动作 → 停顿/回弹 → 循环衔接”。动作服务聊天含义，例如“收到”可以是一次点头加抬手，“无语”可以是缓慢侧目加停顿，避免整套只用抖动、缩放。循环可以回到起点，也可以保持结果再自然重启，由表达决定。

时长和帧率按动作决定，可从 1～3 秒、每秒 8～15 帧开始试，这是制作起点，不是微信平台硬规则。夸张动作仍需维持头身比例、标志配饰和角色辨识度。

保持统一画布、相机、锚点和基准比例。生成帧时逐帧引用角色参考和关键姿态，避免每帧独立随机重画造成身份、线条和材质闪烁。

## 方向草样与最终制作

方向草样用于选角色与风格，可用少量关键帧验证动作。正反播放适用于点头、呼吸等往返动作；摔倒、融化、打字等动作需要各自合理的恢复过程，不默认倒放。

最终制作必须查看原速播放与逐帧对照。定稿时增加必要的过渡帧，保留有意义的停顿，而不是把同一帧重复写入高帧率文件。不要仅凭标称帧率判断流畅度，也不强迫每个动作达到同一个帧率。

单独设计恢复和循环衔接，不强行让跑出画面的角色瞬间回到起点。首尾姿态相近也要检查速度、位置与道具是否连续；插帧或提高帧率不能修复多余肢体和身份漂移。

## 帧间稳定检查

- 每张先确定角色参考、共用画布、固定背景/道具和动作区域；静止部分尽量复用图层或素材。
- 所有帧采用同一个缩放与位置规则，不能每帧按主体外接框自动居中，否则正常动作也会带动整张画面跳动。
- 如果某个桌角、背景或其他区域确实全程不动，在导出清单中用 `stable_regions` 指定区域。只标不被动作遮挡的部分，不能把会运动的整个人物框成静止区域。
- 脚本将这些区域分别合成到浅/深背景，与首帧计算可见像素的归一化平均差异（0～1），取较大值，超过阈值时标出帧号。全透明区域中不可见的 RGB 差异不计入。它只提供复查线索，不自动纠正位置、变形，也不声称能识别角色身份漂移。
- 对五官、头身比例、配饰、线条和材质仍要逐帧视觉对照。错误帧优先局部重做，不靠移动整张图掩盖形体变化。

## 渲染与导出

1. 先看关键帧，再渲染短循环。已有形象直接沿用，不为做动画重设角色。
2. 保留动画源文件或帧序列，以及对应帧时长。
3. 导出真实 240×240 动画 GIF，设置循环。不能把单帧 PNG 改扩展名，不能把静态 GIF 当成动态交付。
4. 全部帧使用一致的调色板/透明索引策略；按内容选择 disposal，检查透明背景上前帧残留与闪边。GIF 透明度有限，柔边需在浅/深背景实看。
5. 使用下面的导出工具，先共享调色板、合并连续相同帧的停留时间，保持原时间线。若仍超限，返回源素材减少冗余细节；需要改动作、删关键帧或改节奏时作为明确设计调整处理，不静默统一降帧率。

## 统一导出工具

`scripts/export_animation.py` 复用 Pillow，无需 FFmpeg。它接受独立静态帧或 sprite sheet 中明确指定的裁切区域，按清单原顺序导出；不自动倒放，不插帧，不改变停顿时长。

在源文件旁保存 `sequence.json`，所有文件路径相对该清单，源文件应在清单目录内部。例如：

```json
{
  "stage": "draft",
  "frames": [
    {"file": "frames/0.png", "duration_ms": 400},
    {"file": "frames/1.png", "duration_ms": 160},
    {"file": "frames/2.png", "duration_ms": 500},
    {"file": "frames/1.png", "duration_ms": 160},
    {"file": "frames/0.png", "duration_ms": 100}
  ],
  "stable_regions": [
    {"name": "desk-corner", "rect": [10, 190, 20, 20], "threshold": 0.03}
  ]
}
```

`stage` 标为 `draft` 或 `final`，只是当前阶段，不表示通过审核。`duration_ms` 为 10 毫秒的整数倍（GIF 时间精度），工具拒绝不符合精度的输入，不自动舍入。帧数 2～240。源画布大小必须一致；统一等比缩放并留边到 240×240，不拉伸。

从帧网格提取时，帧条目可增加 `"crop": [x, y, width, height]`，坐标基于源图。网格尺寸必须经过检查，格数或边距不符时不要盲目等分。逐帧检查完整手脚、头顶符号、道具及边缘是否越格；越格或混入邻帧时重新排布或生成独立帧，不能裁掉自身肢体来隐藏邻格残片。优先输出独立帧，统一主体基准比例并为最大动作预留空间。稳定区域坐标则基于导出的 240×240 画布；没有适用区域可以省略 `stable_regions`。

```bash
python3 <skill目录>/scripts/export_animation.py <项目>/sources/sequence.json --output-dir <项目>/previews/export-01
```

输出目录必须是新目录，包含：

- `animation.gif`：240×240 无限循环 GIF，共用调色板和透明索引。
- `report.json`：各帧时长、总时长、大小、调色板尝试与稳定区域的复查提示。
- `contact-light.png`、`contact-dark.png`：带帧序号与时长的逐帧对照，供检查角色与边缘。

先尝试 255 色，超限时依次尝试 192、128、96 色；每次均保留原时间线。不超过 500000 字节时停止，但仍需看压缩后的画质。仍然超限则保留候选文件、在报告中标记 `size_passed: false` 并返回退出码 1，不能将其当成合格素材复制到交付目录。

GIF 只支持二值透明。默认 alpha 阈值 128，可显式传 `--alpha-threshold` 调整，必须用浅/深背景检查。脚本不会修复假透明或背景污染。对照图来自源帧，也要实际播放和逐帧看最终 GIF，尤其检查拖影、锯齿、细节丢失与首尾衔接。

命令退出码 0 表示大小检查通过，不代表静止区域、角色一致性或动作质量通过。只有完成这些视觉检查后，才把确认的 GIF 复制到 `delivery/stickers/`，继续运行整套校验。

## 检查

- 用实际播放看节拍与首尾衔接，并逐帧看角色变形、闪烁、拖影、缺帧。
- 字幕不要随帧跳位，除非动作设计有意如此。
- 在聊天大小、浅色和深色背景检查透明边缘与动作可读性。
- 重新播放最终压缩的 GIF；源动画流畅不等于导出文件流畅。
- 帧数和循环字段只是技术检查，不能替代观看动画。
- 每张最终 GIF 均需在浅、深底查看全帧并原速循环播放；源帧对照不覆盖编码后的丢色、拖影或边缘问题。将已查项、未查项和实际缺陷写入 `review.md`。无法观察播放时标记待播放验收，不声称全部视觉检查通过。
