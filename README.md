# Expression Design

把一个主题或已有形象，发展成一套风格统一、表达各异的微信聊天表情。

这是一个供 Agent 使用的 Skill，以微信表情专辑为交付目标，支持静态与动态制作，包含表达规划、角色延续、按需联网参考、独立评审、精确导出和受检打包。暂不扩展其它平台。当前版本 **v0.2.8**。

## 能得到什么

- 一套名称（≤8字、无标点，建议≤5字）、介绍（≤80字）和默认8张表情，可指定8～24张。
- 详情页横幅、表情封面、聊天面板图标各 1 张。
- 按聊天含义命名的独立文件，例如 `收到.gif`、`咖啡续命.gif`。
- 素材清单、检查记录，以及通过交付检查后生成的 ZIP。

配套图遵循不同要求：横幅无字、采用与微信底色有区分的明朗背景，避免白底和透明；封面用透明正面半身/全身，除纯文字表情外避免文字；聊天图标用透明正面头部，50px下仍清晰。封面/图标不加白描边，避免锯齿和多余装饰。白色角色身体仍保留白色填充。

有主题时探索角色与画风；已有形象时直接延续角色。既可以做日常聊天，也可以围绕职场、学习、情侣或自定义的梗规划表达，避免只凑一套喜怒哀乐。

## 安装与开始

在支持 skills CLI 的环境中运行：

```bash
npx skills add oneszc/Expression-design
```

也可以将完整仓库安装为 Agent skills 目录下的 `expression-design` 文件夹。保留 `SKILL.md`、`references/`、`scripts/` 和 `requirements.txt`，不要只复制入口文件。

安装后，直接向 Agent 描述需求：

**从一句话开始**

> 帮我做一套“周一不想上班”的微信表情包。

**延续已有形象**

> 沿用这张角色图做 8 张动态微信表情，保留黑白线条和慵懒气质，主要和朋友聊天用。

**带上参考要求**

> 做一套“别急着学 AI”的搞笑动态表情，先搜最近流行的表情表达作参考。

### 使用前需要什么

Skill 本身不内置图像模型。实际出图依赖 Agent 可调用的图像生成或编辑工具；动态还需要连续动作制作、导出，以及评审 Agent 能观察原速播放的能力。

默认评审流程需要独立子 Agent。没有子 Agent 或缺少必要观察能力时，会说明缺口，不能把自评或未观察结果当成独立评审通过。用户明确接受人工验收等替代流程时，记录例外，不静默降级。

随附脚本需要 **Python 3.10+、Pillow**。FFmpeg、Node 和具体动画工具按制作路线选用，不要求全部预装。Agent 会先检查依赖，缺失时说明用途、安装方式及替代路线，按授权安装后复检。详见 [环境与工具选择](references/environment.md)。

## 制作流程

### 1. 确定模式、风格与主题

只询问尚未明确的项目，尽量在同一轮完成：

| 项目 | 选择方式 |
|---|---|
| 制作模式 | 静态或动态，单选 |
| 表情风格 | 建议 1～2 项，如简笔画＋丧/佛系；支持其它自定义 |
| 表情主题 | 选择主主题，如工作/职场；支持其它自定义 |

优先使用 Agent 宿主提供的原生问答卡片或弹窗；不支持时回退文字列表。界面和多选能力取决于宿主。已有角色默认沿用画风，不强迫重新选择。完整选项见 [入口选择](references/preferences.md)。

### 2. 看样张，选方向

只有主题、还没有角色时，展示三个有实际视觉差异的方向。已有形象时跳过重新选角，先做少量代表表达，检查角色延续和动作表现。

样张经过独立评审后再主动展示。动态方向使用真实短循环；文字风格标签和动作九宫格不能代替实际效果。用户选定后扩展整套，选择原话与适用范围保存在本地项目中。

用户要求搜热门表情时，先找参考并记录来源、日期与热度依据，提炼视觉、聊天语气和动态规律，应用于本套原创设计。没有热度依据的只称参考案例；搜索不可用时说明缺口。普通创作不强制搜索。详见 [联网参考](references/research.md)。

### 3. 制作与独立评审

先设计表达、关键姿态和动作节拍，再按需要选择逐帧、可变形分层或混合方式。动态检查实际位置与支撑点、恢复过程和循环衔接，避免机械摆动或动作结束后额外晃动。

独立子 Agent 查看实际候选文件并评分：

| 维度 | 满分 |
|---|---:|
| 角色与风格一致性 | 25 |
| 表达与需求匹配 | 25 |
| 制作质量 | 35 |
| 聊天尺寸可用性 | 15 |

每项须满足 **总分 >80、表达分 ≥18/25、无关键缺陷、必要检查完整**，整套也需通过横向评审。动态要检查最终文件全部帧、浅深底，并实际观察原速至少两轮；缺证据时标为待检查，不凑分放行。

不合格项按具体意见返修，默认每项最多 2 轮。返修后重新评审新文件，不能沿用旧分数。达到上限或缺少能力时报告原因，不把失败候选凑进合格交付。

部分生成工具会自动展示过程预览，无法关闭时会提前说明；这些预览不代表已通过评审。评分是设计判断，不保证用户喜欢，也不等于微信审核。详见 [独立评审与返修](references/review.md)。

### 4. 检查后交付

最终打包工具核对实际规格、清单与素材哈希、完整评审覆盖、分数、缺陷、观察记录和整套结论，通过后才生成正式 ZIP。修改过文件或清单后，旧评审不能继续放行。

程序检查名称/介绍、编码/尺寸/体积，以及封面/图标的透明像素，核对微信配套图的专项评审记录；无字、故事性、白描边、构图与跨专辑重复仍需实际视觉评审。程序不能证明观察描述真实或替Agent判断美观。详见 [微信交付要求](references/wechat-delivery.md) 和 [评审报告与受检打包](references/review-report.md)。

## 本地文件与素材范围

默认项目目录为工作区内的 `output/expression-design/项目名/`，不写进 Skill 安装目录。目录按实际产物创建：

```text
项目名/
  project.md           # 角色、模式、用户选择与约束
  expressions.md       # 每张的含义、动作、配字与节拍
  sources/             # 参考图、源素材、帧序列
  previews/            # 候选、方向样张、浅深底检查图
  reviews/             # 各轮独立评审，最终报告为 final.json
  review.md            # 已检查项、未检查项和实际问题
  delivery/
    manifest.json
    stickers/
    banner.png
    cover.png
    icon.png
```

ZIP 只包含清单和清单内最终素材。用户源图、提示词、评审记录、过程预览和测试作品留在本机，不默认提交 GitHub。本仓库已忽略默认输出目录及本地 `examples/monday-blues/`；自定义目录仍需检查适用的忽略规则。

用户偏好记录有适用范围，不把单个案例的配色、配饰或个人口味变成所有人的默认。详见 [偏好与经验记录](references/learning.md)。

## 脚本使用与开发验证

以下命令在仓库根目录运行，使用满足版本要求的 Python。若 Agent 已有满足依赖的解释器，可直接复用；需要安装时建议使用项目虚拟环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

**检查整套技术规格**：

```bash
.venv/bin/python scripts/validate_pack.py /path/to/project/delivery/manifest.json --report /path/to/project/validation.json
```

此命令检查编码、尺寸、体积、数量、路径及动图帧，不能代替独立评审。报告写入新路径，不覆盖已有文件。

**从帧序列导出 GIF**：

```bash
.venv/bin/python scripts/export_animation.py /path/to/project/sources/sequence.json --output-dir /path/to/project/previews/export-01
```

导出器保留原时长，使用共享调色板，合并连续重复帧，生成 GIF、浅深底对照和报告。它负责编码，不生成动作；输出目录须为新目录。清单格式见 [动态制作](references/animated.md)。

**根据实际评审生成正式 ZIP**：

```bash
.venv/bin/python scripts/package_reviewed.py /path/to/project/delivery/manifest.json /path/to/project/reviews/round-1/final.json --output /path/to/project/stickers-approved.zip
```

评审格式见 [固定报告格式](references/review-report.md)。检查失败不创建 ZIP，已有 ZIP 不覆盖。该脚本是 Skill 要求调用的交付入口，不是所有 Agent 宿主的系统级拦截钩子。

**运行测试**：

```bash
.venv/bin/python -m unittest discover -s tests -v
```
