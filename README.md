# Expression Design

一个面向微信表情包制作的 Agent Skill。从主题探索角色和画风，或直接沿用已有形象，完成一套有统一风格的聊天表情。

## 使用

把本仓库作为 `expression-design` 文件夹安装到 Agent 的 skills 目录，保留 `references/` 和 `scripts/`。支持 skills CLI 的环境可运行：

```bash
npx skills add oneszc/Expression-design
```

示例：

> 帮我做一套“周一不想上班”的微信表情包。

> 沿用这张角色图做 8 张动态微信表情，性格懒洋洋，主要和朋友聊天用。

未说明静态或动态时，Skill 会先询问。只有主题时展示多个实际样张方向；主要形象已确定时跳过方向对比。过程中只问影响结果的核心问题。

入口统一收集三组选择：制作模式（静态／动态，单选）、表情风格（建议 1～2 项，如简笔画＋丧/佛系）和表情主题（一个主主题，如工作/职场）。风格、主题均支持“其它，自行输入”。已说明的要求直接沿用，已有角色不强制重选画风；只问尚缺项，尽量在同一轮完成。优先使用 Agent 提供的原生选择弹窗/问答卡片；具体界面及多选取决于宿主能力，不支持时回退文字选择。完整选项与处理方式见 [制作模式、风格与主题选择](references/preferences.md)。

一句话也可带上参考要求，例如“做一套别急着学 AI 的搞笑动态表情，先搜最近流行的表情表达作参考”。用户要求时，Skill 会使用 Agent 当前可用的联网工具，记录来源、日期和热度依据，提炼视觉、语气与动作规律后继续原创设计；搜到不等于热门，缺少证据时明确标为参考案例。普通创作不强制搜索，搜索不可用时说明缺口并保留原创制作路线。详见 [联网参考与特征提炼](references/research.md)。

## 交付

- 整套名称（已有名称沿用，否则提供候选）。
- 8～24 张静态或动态表情。
- 详情页横幅、表情封面图、聊天面板图标各 1 张。
- 文件清单、规格检查结果，以及实际预览。

表情文件按聊天含义命名，例如 `周一开机失败.gif`、`咖啡续命.gif`，不默认使用编号。同名按动作或语气区分，清单和 ZIP 使用一致的语义文件名。

生成项目默认写入用户工作区的 `output/expression-design/`，不写入 Skill 安装目录，也不默认提交到 GitHub。本仓库已忽略该输出目录和本地 `examples/monday-blues/` 测试产物；源图、预览、报告及交付 ZIP 都在排除范围内，文件仍保留在本机。

图像与动画制作依赖 Agent 当前可用的生成、编辑或渲染工具；本仓库没有内置图像模型，不需要固定厂商密钥。缺少出图能力时只能完成方案，不能生成实际素材。动态路径需要真实动画制作能力。

Skill 会在制作前检查所选路线的能力与依赖。随附校验和 GIF 导出需要 Python 3.10+ 与 Pillow；FFmpeg、Node 和具体动画工具均为按需可选，不要求预装。缺失时给出用途、适用的安装提示和替代路线；按授权安装后重新验证。详见 [环境与工具选择](references/environment.md)。

## 规格检查

Python 3.10+，Pillow：

```bash
python3 -m pip install -r requirements.txt
python3 scripts/validate_pack.py /path/to/project/delivery/manifest.json --report /path/to/project/validation.json
python3 -m unittest discover -s tests -v
```

动态表情可使用统一导出工具：

制作先设计关键姿态与动作节奏，再按动作选逐帧、可变形分层或混合方式。复用素材不等于只做刚性旋转和缩放；先验证少量代表动画的自然度、画风及接触关系，再批量扩展。以下工具负责编码，不负责生成动作或判断表演质量。

```bash
python3 scripts/export_animation.py /path/to/project/sources/sequence.json --output-dir /path/to/project/previews/export-01
```

工具支持帧序列与帧网格裁切，保留每帧时长，统一调色板并合并连续重复帧，导出 GIF、浅/深背景逐帧对照和检查报告。可指定静止区域，标出帧间变化；角色身份、比例和动作质量仍需视觉检查。清单格式与草样/最终动画标准见 [动态制作说明](references/animated.md)。

规格基线采用用户提供的微信素材概览截图，详见 [微信交付要求](references/wechat-delivery.md)。检查通过仅代表文件符合该基线，视觉表现、实际聊天效果与微信审核需另外核对。Skill 不自动向微信投稿。
